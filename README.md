# 大盘云图（dpyt.org）复刻版 · 带自建行情后端

对 <https://dpyt.org> 的完整复刻：前端（Canvas 2D 手写渲染、全部交互与弹窗）
＋ 后端（自建行情聚合服务），数据**实时拉取、定时自动刷新**，不依赖原站即可运行。

原站是 Next.js 单页应用、全客户端渲染；本复刻版拆解为
「静态 HTML/CSS/JS 前端 + 单文件 Python 行情后端」，无需构建步骤。

---

## 一、快速开始

```bash
cd dpyt-clone
python3 proxy.py 8231          # → http://127.0.0.1:8231/
```

`proxy.py` 同时承担两件事：直出静态文件（`index.html`、`assets/*`）与提供
`/api/heatmap/*` 行情接口，因此只需这一个进程，无构建步骤、无第三方依赖。

运行形态与降级行为：

| 运行状态 | 数据来源 | 自动刷新 | 侧栏「数据来源」标注 |
| --- | --- | --- | --- |
| `proxy.py` 正常 | 腾讯行情实时抓取 | ✅ 默认每 10 秒 | `实时接口` |
| 后端异常但页面从 http 打开 | 打包快照（2026-11-13 收盘） | ❌ | `本地快照（接口暂不可用）` |
| `file://` 直接打开 `index.html` | 打包快照 | ❌ | `本地离线快照` |

## 二、数据链路

```
浏览器前端 (assets/js/main.js)
   │  fetch /api/heatmap/{overview,treemap,quotes,quotes/stream,status}
   ▼
proxy.py（同源 HTTP 服务，ThreadingTCPServer，端口由参数指定）
   │  静态文件直出  +  /api/* 交给 datasource.py 聚合
   ▼
datasource.py
   ├─ 股票池骨架：assets/data/all-day.js（5579 只的 代码/名称/一级板块/二级板块/交易所）
   │            + assets/data/period-index.json（非日周期的 3 只新增个股与新版指数成分）
   └─ 实时行情：腾讯批量行情 https://qt.gtimg.cn/q=sh600519,sz000001,...
              └─ 每批 900 只 × 7 批，并发 3，全市场约 2~4 秒
              └─ 单条记录已含 当日/近5日/近20日/年初至今 四个涨跌幅
              └─ 日 K https://proxy.finance.qq.com/... 用于「比昨日」成交额
```

浏览器端策略（Stale-While-Revalidate）：

1. 先用**打包快照**立即上屏（首屏 <1 秒就有画面，不等后端）；
2. 并行请求 `/api/heatmap/overview` + `/api/heatmap/treemap`，拿到后重绘；
3. 交易时段再拉 `/api/heatmap/quotes/stream` 补充逐笔价格与成交额；
4. 页面可见时按「设置 → 自动刷新」的间隔（默认 10 秒）重复第 2、3 步；
5. 连续 3 次请求失败 → 判定离线，降级到快照，并每 30 秒探测一次恢复。

## 三、为什么用腾讯行情而不是东财

原计划按需求接东方财富 `push2.eastmoney.com`。实测结论：

- 东财 `api/qt/clist/get` 单页上限只有 100 条（`pz` 更大也只回 100），
  全市场 5579 只需要 60 次分页请求；
- 本机到 `push2.eastmoney.com` / `push2his.eastmoney.com`（含 `1.`~`99.` 分片域名、
  `push2delay`）在连续几轮抓取后**全部返回 `http=000`（连接被重置），
  冷却 20 分钟后仍不可用**；
- 腾讯 `qt.gtimg.cn` 在同一台机器上稳定可用：单批 900 只、7 批约 2 秒，
  且一条记录同时给出 4 个周期的涨跌幅，字段已逐只交叉校验
  （如 600467 好当家：当日 10.08% / 近 5 日 22.97% / 近 20 日 18.18% / 年初至今 5.24%）。

因此**主行情源用腾讯**。数据源与聚合逻辑是解耦的：
`datasource.py` 里只需改 `_fetch_quotes()`（抓取）与 `PERIOD_FIELD`（周期字段）
即可换回东财或其它源，接口契约不变。

```

datasource.py                 行情聚合：股票池、腾讯抓取、周期统计、成交额历史
cache/turnover.json           按交易日累计的成交额历史（用于「比昨日」）
assets/
  css/app.css                 原站编译产物样式（原样保留）
  css/clone.css               复刻版补充组件样式（弹窗/悬浮卡/设置抽屉…）
  js/core.js                  配色、布局、绘制核心（从原站 bundle 反解）
  js/main.js                  状态、数据装载、交互、弹窗、快捷键、网络层
  js/data.js                  数据挂载点
  data/<market>-<period>.js   36 份快照（9 市场 × 4 周期）+ overview.js
  data/period-index.json      非日周期的股票池补丁（原站日周期与非日周期用了两批数据版本）
  img/logo-mark.svg           自有品牌标记（矩形树图意象，非原站 logo）
  favicon* / apple-touch-icon 由同一标记生成的站点图标
```

### 后端接口

| 路由 | 说明 |
| --- | --- |
| `GET /api/heatmap/overview?period=day` | 9 个市场的指数涨跌幅、成交额、更新时间 |
| `GET /api/heatmap/treemap?period=day&market=all` | 热力图数据（板块树 + 个股 + summary） |
| `GET /api/heatmap/quotes?period=day&codes=600519,...` | 指定代码报价 |
| `GET /api/heatmap/quotes/stream?period=day` | NDJSON 快照（`start` / `quotes` / `complete` 三行） |
| `GET /api/heatmap/status` | 自检：股票池大小、报价数、行情时间、耗时、是否交易时段 |

响应头附带 `x-heatmap-snapshot` / `x-heatmap-quote-at` / `x-heatmap-quote-count` /
`x-heatmap-universe-count` / `x-heatmap-source`，前端据此标注数据来源。

## 五、实现要点

- **渲染**：Canvas 2D 手写，非图表库。布局是二叉递归切分（按累计市值找最接近
  一半的切点，沿长边切分，递归下沉到个股），一级板块标题条高度、二级板块内边距、
  个股间隙、缩略图紧凑参数等全部数值取自原站 bundle。
- **配色**：7 套主题（经典 / 柔和 / 低饱和 / 高对比 / 日落 / 极光 / 水墨）× 明暗两套；
  个股色 = soft→strong 之间按 |涨跌幅| 插值，归一上界 10%、幂次 0.82；
  板块标题条在同色基础上按明暗压暗 8% / 12%；图例渐变取 9 个刻度点生成。
- **面积**：按周期分流，与原站口径逐股对齐：
  - **日周期** = `快照权重 × 实时价格 / 快照价格`。快照权重取自原站数据（与其股本口径一致），
    再按腾讯实时价折算，因此布局与原站几乎逐像素一致，同时随价格实时变化；
  - **周 / 月 / 年周期** = 腾讯实时流通市值（f44）。实测原站这三个周期的个股 `value`
    与腾讯 f44 精确到亿元完全相等（如中国石油 20062 亿、贵州茅台 17942 亿），且三者权重相同。

  设 `DPYT_LIVE_VALUE=1` 可强制全部周期都用 f44。
- **股票池**：原站自身在日周期与非日周期用了两批数据版本 —— 日周期 5579 只（旧快照），
  周/月/年 5582 只（含 3 只新增个股，且指数成分已更新）。`data/period-index.json`
  保存了这份差集与新版指数成分，`datasource.py` 的 `members(market, period)` 据此按周期返回。
  非日周期中 3 只新股没有历史涨跌幅，接口返回 `null` 且不计入涨跌家数（与原站一致）。
- **涨跌家数**：实测原站侧栏的判平口径随视图而变，这里完全照抄：
  「A 股全图 + 日周期」用严格正负（|涨跌| 恰为 0 才算平盘）并剔除无成交的停牌股，
  得 765 / 58 / 4748；其余组合（所有子市场，以及周/月/年周期）统一用 |涨跌| ≤ 0.1% 判平。
  四个周期 + 九个市场的「上涨 / 平盘 / 下跌 / 成交额 / 比昨日」整行文本与线上逐字一致。
- **「比昨日」**：优先用 `cache/turnover.json` 里按交易日累计的历史值；
  首日没有历史时，用指数日 K 第 9 个字段（成交额，万元）外推：
  `昨日全市场 ≈ 昨日两市成交额（沪 sh000001 + 深 sz399107）＋ 今日北交所成交额 × (北证50 昨日/今日成交额)`。
  实测 2026-11-13 得昨日 19458.8 亿 vs 原站 19458.7 亿，缩量 2788 亿与原站完全一致。
  只有「A 股全图」显示这个对比，其余市场与原站一样显示 `--`。
- **自选**：本地 `localStorage`，上限 80 只，支持导入/导出 JSON；
  有自选时侧栏「自选」按市值加权计算涨跌幅。

## 七、保真度实测

以 1438×859 画布、40×20 = 800 个采样点逐点比对原站（同一市场 A 股全图）：

| 周期 | 采样点颜色完全一致 | 平均通道偏差 | ≤12/255 容差内 |
| --- | --- | --- | --- |
| 日（默认视图） | **97.1%** | 2.02 / 255 | 97.8% |
| 月 | **69.0%** | 4.24 / 255 | 95.5% |

- 日周期的差异集中在标题文字的字形渲染（原站用 Avenir Next Condensed / DIN Condensed，
  系统未安装时回退字体度量不同），不是布局或配色偏差；
- 月 / 年周期面积改用腾讯 f44 后与原站口径仍有极小的个股权重差（见「已知差异」），
  切分位置因此有偏移，导致固定采样点落到不同股票上；但颜色分布整体一致（95.5% 在容差内）。
- 图例渐变字符串、侧栏文案、底栏 7 条操作提示、弹窗全部文案逐字一致
- 布局几何（canvas、侧栏 162px、底栏 41px）与原站一致

### 数据接口逐项比对（36 组视图）

9 个市场 × 4 个周期 = 36 组，逐组比对 `treemap` 接口的涨跌家数与加权涨跌幅：

- **35 组完全一致**（家数完全相同、涨跌幅到小数点后 4 位相同）；
- 唯一残留：深证 A 股年周期 −7.3868% vs 原站 −7.3929%（差 0.006pp）。
  已定位为个股权重微差（如 301507 民生健康：原站 40.6 亿 vs 腾讯 f44 12.5 亿），
  用原站权重重算即得 −7.3929%，说明涨跌幅本身无误。

侧栏「上涨 / 平盘 / 下跌 / 成交额 / 比昨日」文本另做了前端渲染比对：
A 股全图四个周期、以及上证/深证/沪深300/主板在周与年周期，全部逐字一致。

### 已知差异

- 面积权重：日周期保留原站股本口径（快照权重 × 实时价格折算），因此同一交易日与原站布局一致；
  周/月/年周期用腾讯 f44，与原站比较时个股权重会有 1% 上下的差（极端个股如新股/解禁股可达数十 %），
  导致布局有微移；换到后续交易日后日周期的权重也会随价格漂移，与原站有轻微出入。
- 涨跌幅、价格、成交额均为腾讯实时值，与原站（其自有数据源）在同一时点可能有个别股票
  末位小数差异；九个市场侧栏的指数与加权涨跌幅已全部对齐（如中证 A50 +0.31%、A 股主板 -0.47%）。
- 腾讯行情时间取自最后成交时刻（收盘后固定在 15:00~16:15 区间的数据刷新时刻）。

## 十、名称完整显示

个股 / 板块名称**在任何缩放级别、任何视口宽度下都完整显示，不截断、不加省略号**。
（原站为固定字号 + 二分截断，会出现「招商银行」被截成「招商银」。）

- 画布文字（`core.js`）：新增 `fitText(ctx, text, weight, size, maxWidth, minSize)`，
  宽度不足时**按比例缩小字号**直到整名放得下（`minSize` 默认 `0`，即不设下限、永不截断）。
  已接入全部 9 处名称绘制点：个股大/中/小/极小四档、一级板块标题条、二级板块巨大/中等/小档、
  以及缩略图折叠模式。
- 小尺寸个股块：名称与涨跌幅同行，**名称优先**——两者都能完整放下才显示涨跌幅，否则把整宽让给名称。
- DOM 侧（`clone.css` / `index.html`）：`.dp-li-name`、`.dp-tip-name`、`#filter-hint` 去掉
  `text-overflow: ellipsis`，改为允许换行（新增 `.dp-wrap` 工具类）。

实测（hook `CanvasRenderingContext2D.fillText`，与全部 5,557 个名称比对）：

| 视口 | 缩放 | 被截断名称数 | 「招商银行」字号 |
| --- | --- | --- | --- |
| 1600×900 | 1× | **0** | 16px |
| 1600×900 | 1.6× | **0** | 18.75px |
| 1280×800 | 1× | **0** | 15px |
| 1280×800 | 1.6× | **0** | 18.2px |

## 十一、刷新不闪烁

自动刷新（默认 10 秒一轮）时画面**完全静止**：不闪白、不整屏模糊、侧栏文字不跳动。
为此改掉了四个会造成视觉打断的地方：

| 问题 | 原因 | 改法 |
| --- | --- | --- |
| 整屏一帧空白 | `paint()` 每次都执行 `canvas.width = …`，赋值会丢弃并重建整个后备缓冲 | 只在尺寸真的变化时才赋值，否则复用现有缓冲 |
| 整屏模糊一下 | 每轮刷新都会显示 `#loading-overlay`（`inset-0` + `backdrop-blur-[10px]` + 92% 不透明底色） | 遮罩只在首屏显示，之后的数据刷新绝不覆盖画布 |
| 侧栏文字跳动 | 更新时间旁每轮插入/拔出旋转图标，撑动文本位置 | 转圈只在首屏出现，刷新时原地不动 |
| 无谓重排/重绘 | 每轮都用 `innerHTML` 全量重建市场列表与统计块 | 内容指纹相同就跳过写入（`setHtml`/`setText`），同值样式不重设 |

另外数据层也做了收敛：`refreshLive()` 只有在**行情时间（`updatedAt`）真的变了**时才视为「有变化」，
`refresh()` 用数据指纹（`dataSig()`）判断，指纹相同就跳过 `rebuildModel()` 与 `invalidate()`。

实测（CDP 探针，逐帧采样）：

| 场景 | canvas 尺寸赋值 | 遮罩显示 | 侧栏 DOM 写入 | 空白帧 |
| --- | --- | --- | --- | --- |
| 25 秒自动刷新（3 轮） | 0 | 0 | 0 | 0/1501 帧 |
| 强制数据变化触发重绘 | 0 | 0 | — | 0 |
| 切换 9 个市场 / 4 个周期 | 0 | 0 | 正常更新 | 0 |
